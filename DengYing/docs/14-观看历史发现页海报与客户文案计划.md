## 0. 0.3 修订说明

0.2 的方向成立，但不能直接实施。本版修正以下事实和方案：

1. 亮屏续播的根因不是 `LaunchedEffect` 重新执行；根因是 `MainActivity.onStart()` 无条件恢复。`DiscoverResume.heldByUser` 到不了这条路径，已删除该方案。
2. 观看历史不是“没有写入”，而是“写入时机不满足 3 秒验收”：全屏和内嵌都按 5 个 tick 写，暂停和离页不补写；`onCleared` 实际是异步协程。本版把首次写入、暂停补写、离页补写分开写清。
3. `Store` 的失败路径不止 `ensure()` 和版本信封；`putString` 提交失败、异常、`saveHistoryBlocking()` 的新版本路径和调用方忽略 Boolean 都要覆盖。
4. 删除令牌设置会切断登录/注册唯一可用的令牌来源；“账号只保存在这台手机”与远端登录接口不符。本版把令牌来源列为实施前决策，不把虚假承诺写进客户文案。
5. 只提供 `LocalIndication` 关不掉 Material3 的显式 `ripple()`；本版同时提供 `LocalRippleConfiguration = null`，并修正 `IndicationNodeFactory` 的节点写法和 `drawContent()`。
6. 新增第 7 项目标：发现页无限流不能触底。现有“无限流”只是有限池去重追加，池子耗尽后 `addBatch()` 不再增长。
7. 新增第 8 项目标：发现页优先可播且完整的源。现有 `discoverRawUrl()` 固定取第一条线路第一集，不知道 `playGap`、预告线和线路集数。
8. 新增第 9 项目标：自动更新弹窗只在冷启动出现。现有 `NavGraph` 根部 `LaunchedEffect(Unit)` 在 Activity 重建或新组合时也会触发。
9. 本期范围明确为 Android 工程先行；iOS/OHOS 的旧文案登记后续同步，不声称三端已完成。

## 1. 目标与范围

本次解决九件事：

1. 观看历史在未登录时也要能记、能看。登录不是本地观看记录的门槛。
2. 发现页横图海报要铺满 16:9 播放窗。用放大裁切，不要两边或上下留空。
3. 发现页播过视频、回到主页并已经暂停后，息屏再亮屏不得自己继续播。
4. 面对用户的文案不要出现来源名、接入过程、内部术语。包括直播频道里的 Hululu007、首页空态里的「蓝光4k」「天翼视讯」、详情页把播放链缺口原文交给用户、登录页的令牌 / 接口说明、注册页的云同步与邀请码。
5. 任何可点控件在按下和松开后都不出现灰色波纹或灰色按压底。
6. 详情页选集区「下载 / 完成」与「正序 / 倒序」两个按钮尺寸一致。
7. 发现页要能一直下滑，不能出现“到底了”的空尾。优先拉取更多分类页；池子耗尽后允许按轮次复用，但不能让列表停止增长。
8. 发现页自动播放优先选择可播且完整的源：排除已知 `playGap` 和已停用源，线路优先非预告、集数多的线路，并保留全片兜底。只有试看时保留角标，不能假装完整。
9. 自动检查更新之后的弹窗只在冷启动进入 App 时出现。热启动、回前台、旋转和 Activity 重建不自动检查、不自动弹窗；用户手动「检查更新」不受限。

不在范围：

- 改观看历史的存储键、信封格式或容量上限；接云同步。
- 删除 `AhAuth` 请求实现；把登录改成账号体系重构。
- 重写全局播放链解析、全局 `findFullSource()` 的“先成功先用”策略或源启用持久化策略。第 8 项只改发现页入口的过滤和线路选择。
- 换海报加载库；改三端版本号；发布 Release。
- 新增内容源、推荐系统或在线源市场。第 7 项的“无限”只基于现有内容池和分类分页。
- 本期同步修改 `DengYingIos/`、`DengYingOhos/` 的副本。它们仍保留旧文案和旧播放路径；需要另立跨工程任务。

### 1.1 实施前决策

**D1（阻塞第 4 项）：令牌来源。**
当前 `AhAuth` 在登录/注册前强制读取 `app_auth_token`，唯一写入点是登录页「令牌设置」对话框。直接把入口从客户界面删掉，新装或令牌过期后登录/注册必然返回 `MSG_NO_TOKEN`。实施前必须二选一：

- 推荐：保留 `AhAuth` 和表单代码；把令牌入口移到 debug-only 维护页；release 没有构建期令牌时，登录/注册页显示「登录暂不可用」，不渲染必然失败的账号密码表单。`docs/02` FR-628 的证据改成“debug 维护入口 + release 不显示”。
- 备选：先完成服务端签名令牌或构建期注入；在此之前不得删除现有令牌入口。

本计划不把“删除令牌设置后登录仍可用”写成既成事实。

**D2（影响第 7 项）：无限流是否接受重复。**
现有内容池有限。要做到“永不重复”，必须新增内容源或新分页接口，超出本计划。默认方案是：分类页还能翻时优先追加新内容；池子耗尽后按轮次重新洗牌复用，卡片 key 带轮次，列表不触底。若产品要求永不重复，请先确认新内容来源。

**D3（限定第 4 项）：来源名的例外。**
直播页、首页空态、推荐失败提示不再出现来源名。`源状态` 是用户管理片源的页面，必须显示显示名才能启用/停用；详情页选源也需要可区分的线路标签。这里的来源名是功能信息，不是营销文案。若要求这两处也完全不出现来源名，需要另做“线路 1/2/3”的中性命名方案并同步需求矩阵。

## 2. 现状事实（来自当前代码，非本次实测）

### 2.1 观看历史

1. **写入不看登录。** `PlayerViewModel.persistHistory()`（`ui/src/commonMain/kotlin/com/dengying/player/ui/viewmodel/PlayerViewModel.kt:1174-1190`）只要求 `vodId != 0` 且 `source` 非空；`DetailViewModel.saveInlineHistory()`（`DetailViewModel.kt:1111-1127`）同口径；`Store.saveHistory()`（`shared/src/commonMain/kotlin/com/dengying/player/data/store/Store.kt:335-358`）和 `HistoryViewModel.reload()` 都不读 `AhAuth`。
2. **3 秒不是写盘阈值。** 3 秒是续播判定（`pos > 3000`）。全屏在 `PlayerViewModel.kt:376-394` 每 5 个 tick 写一次，`onPaused()` 在 `:300-303` 只停循环；内嵌在 `DetailViewModel.kt:1047-1067` 每 5 个 tick 写一次，`:1069-1071 onPaused()` 只改状态，内嵌文件没有 `onCleared`。因此内嵌播放 3–4 秒离页可能完全没有历史。
3. **离页写不是同步。** `PlayerViewModel.kt:1861-1905 onCleared()` 的注释说“直接同步写”，实际是 `CoroutineScope(ioDispatcher).launch { store.saveHistoryBlocking(item) }`。立即回历史存在竞态，进程被杀还可能丢最后一次写。
4. **Store 失败路径不完整。** `Store.kt:169-180 writeList()` 对 `putString(sync=true)` 返回 false 没有 `warnWrite`；`:335-358 saveHistory()` 还可能因异常或 `putString` false 失败；`:378-398 saveHistoryBlocking()` 遇到更高版本直接 return，忽略 `putString` 返回值。`DetailViewModel.kt:1127` 明确忽略 Boolean。
5. **历史页会把“读取中/失败”显示成空。** `HistoryScreen.kt:53-58`、`:83-85` 与 `HistoryViewModel.kt:18-39` 的 `UiState` 初始为空，没有 loading/error；首帧或读取失败都会显示「暂无播放记录」，制造“写入失败”的假象。
6. **没有登录过滤。** `HistoryScreen` 直接调 `store.getHistory()`；`BttwoAuth.isLoggedIn()` 是源站 cookie，不是 `AhAuth`；debug 包与正式包数据隔离是包级事实。正常路径只有一个 `UiDepsHolder.deps.store`。

### 2.2 发现页海报

`DiscoverVideoCard` 的 16:9 窗口在 `ui/src/commonMain/kotlin/com/dengying/player/ui/pages/IndexScreen.kt:1277-1280`；两处 `Poster` 显式传 `ContentScale.Fit`（`:1306-1312`、`:1320-1326`）。公共 `Poster` 默认已是 `ContentScale.Crop`（`Poster.kt:152-157`），首页推荐大卡没有覆盖这个默认。发现页是唯一把横图固定成“保留比例”的入口。

### 2.3 亮屏续播

1. `MainActivity.kt:66-83`：`onStop` 调 `PlaybackEngineHolder.peek()?.pause()`；`onStart` 在没有 `PlaybackSession` 时直接 `peek()?.play()`。`:75-77` 的注释已经写明“active 仍为 true，`LaunchedEffect(active)` 不重跑”。
2. `IndexScreen.kt:1130-1149` 的 `LaunchedEffect(playingIdx, active)` 只在 key 变化时执行；息屏/亮屏不改变 key，不会重跑。真正让主页出声的是 `MainActivity` 的无条件 `play()`。
3. `DiscoverResume`（`IndexScreen.kt:947-959`，实例在 `:177`）只是普通 `remember`，不是 `rememberSaveable`；其中的 `heldByUser` 即使存在，`MainActivity` 也读不到。
4. 发现页 16:9 卡片整卡 `clickable` 直接 `onOpenDetail(...)`（`:1281-1298`），没有独立暂停按钮；“用户手动暂停”在当前 UI 没有入口。
5. `active = pagerState.targetPage == 2`（`:370`）只表示 pager 目标页，不等于“当前播放所有者”。Home、Category、Mine、Detail、Fullscreen、Back 六个场景不能都用一个 `active` 判断。

### 2.4 客户可见文案

1. 直播页仍写 `Hululu007`（`LiveChannelsScreen.kt:53`），我的页直播副标题仍写 `Hululu007 公开频道清单`（`MineScreen.kt:457`）。
2. 首页空态写「蓝光4k」「天翼视讯」（`IndexScreen.kt:550-552`）；推荐失败同句在 `IndexViewModel.kt:623`、`:747`。`蓝光4k` 是 `Sources.kt:389` 的显示名，也是 `playGap` 源。
3. 详情页把 `SourceConfig.playGap` 原文交给用户（`DetailScreen.kt:641-643`）。`playGap` 不只在详情页：`PlayerViewModel.kt:525`、`:609` 也拼 `errMsg = "该源暂不可播：${src.playGap}"`，`InlinePlayer.kt:485`、`PlayerScreen.kt:371` 会显示。
4. 登录页展示 `app_auth_token`、`refresh_token`、接口路径和 appid（`LoginScreen.kt:278`、`:287-299`、`:319-332`）；QQ 入口仍可点，但结果是 `qqLoginNotReady()` 的原始说明（`LoginScreen.kt:250-270`）。
5. 登录/注册把 `Outcome.Error.message` 原样写入反馈（`LoginScreen.kt:199`、`RegisterScreen.kt:168`）；`AhAuth.kt:65` 提示去令牌设置，`RegisterScreen.kt:227` 仍写「登录服务签名令牌（app_auth_token）尚未取得」。

### 2.5 灰色按压波纹

`ui/src/commonMain` 实际是 `.clickable(` 31 处、`.combinedClickable(` 1 处、`.toggleable(` 1 处，显式 `indication = null` 11 处；其余走 Compose 默认指示。`DengYingTheme` 唯一根在 `ui/src/commonMain/kotlin/com/dengying/player/ui/theme/Theme.kt:124-145`。

Material3 1.9.0 的 `Surface.kt:227-229`、`:333-336`、`:443` 和 `IconButton.kt:182-187`、`:337` 显式传 `indication = ripple()`；`Button.kt:128-137` 委托 `Surface(onClick=...)`。`Ripple.kt:259-267` 在 `LocalRippleConfiguration == null` 时 `removeRipple()`。只提供 `LocalIndication` 不会覆盖这些显式 ripple。

foundation 1.11.1 的 `IndicationNodeFactory.create()`（`Indication.kt:104-125`）返回 `DelegatableNode`，要求节点实现或委托 `DrawModifierNode`，并在 `draw()` 调用 `drawContent()`；`create()` 每次应返回新节点。

### 2.6 选集区两个按钮

`DetailScreen.kt:703-744` 两个 `Box` 都是 `height(36.dp)`、`RoundedCornerShape(18.dp)`、`clickable`、`padding(horizontal = 12.dp)`、`contentAlignment = Center`、`labelMedium`。下载在 `:703-724`，排序在 `:726-744`，中间 `Spacer(8.dp)`，排序仅在 `displayEps.size > 1` 时显示。高度相同，宽度随文字走，所以「下载」与「正序 ↑」不等宽。

### 2.7 发现页无限流

1. `DiscoverPane` 的 `items` 在 `IndexScreen.kt:1006-1015` 用 `remember(pool)` 首批最多放 `DISCOVER_BATCH = 9` 个不重复项。
2. `cursor` 在 `:1017` 从 `countFirstUnique(pool, 9)` 开始；`addBatch()` 在 `:1019-1031` 只追加 `items.none { it.vod_id == v.vod_id }` 的项。所有唯一项都进列表后 `added = 0`，列表停止增长。
3. 近尾触发在 `:1172-1180`：最后可见 index >= `items.size - 4` 时调 `addBatch()`；`LazyColumn` 在 `:1219-1232` 没有 footer、加载态或“到底”状态。
4. `picks` 在 `IndexScreen.kt:255-273` 由六个分类缓存和 tv189 版块合成，`distinctBy` 后有限；`remember(poolReady, discoSeed)` 的 key 不包含分类 `items` 数量，所以 `IndexViewModel.loadMore()` 新增的项不会自动进入池子。
5. `IndexViewModel.loadMore(idx)`（`IndexViewModel.kt:828-894`）已有分页、`hasMore`、`loadingMore` 防重；推荐页 `hasMore` 恒 false。分类页能翻，但发现页没有调用它。

### 2.8 发现页源与线路

1. `discoverRawUrl()`（`IndexScreen.kt:1405-1420`）取详情后直接 `vod_play_url.split("$$$").first().split("#").first()`，固定第一条线路第一集，没有 `vod_play_from` 线路选择。
2. `resolveChainOf()`（`IndexScreen.kt:1065-1084`）已调用 `resolvePlayChain(altLimit = 3, waitForFullSource = true)`，有跨源全片兜底；上游 raw 仍可能是预告或短线路。
3. `Models.kt:111 parsePlayLines(from, url)` 能解析线路；`PlayLinePick.kt:32 chooseDefaultLineIndex(lines)` 优先非预告、再按集数降序；`:55 chooseFullerSourceEpisodeCount(...)` 当前生产未调用。
4. `DetailViewModel.kt:325-334` 已用 `parsePlayLines + chooseDefaultLineIndex`；`PlaybackSession.kt:539 findFullSource()` 并发试候选，谁先成功用谁，不比较候选集数；`:573 resolvePlayChain()` 在试看链时调用它找全片。
5. 分类池没有按 `playGap` 过滤；`ah_ap2233`（显示名「蓝光4k」）当前 `playGap` 非空（`Sources.kt:396`），仍可能进入发现页池。

### 2.9 自动更新

`NavGraph.kt:102-105` 在根层 `LaunchedEffect(Unit) { UpdateNoticeController.autoCheck(deps) }`。`UpdateNoticeController.kt:35-38 autoCheck()` 先看 `UpdatePrefs.shouldAutoCheck(Clock.nowMs())`；`UpdatePrefs.kt:66-69` 的间隔是 `24L * 60L * 60L * 1000L`，键是 `ui_update_last_check_ms`、`ui_update_ignored_tag`。`Available` 时 `manual || !ignored` 才弹窗（`:55-63`）；`UpToDate`/`Failed` 不弹（`:65-82`），但每次结果都会 `markChecked`。

`MainActivity.onCreate(savedInstanceState)` 已存在，但当前没有冷启动标记；`DengYingNavHost` 没有 `coldStart` 参数。Activity 重建或新组合重跑 `LaunchedEffect(Unit)` 时，仍可能自动检查并弹窗。

## 3. 用户看到的结果

### 3.1 观看历史

未登录看一部片，有效播放累计到 3 秒后暂停或离开，回到「我的 → 观看历史」能看到这部片，点进去从上次位置续播。登录与不登录结果一致。

历史页先显示「读取中」；读取失败显示「本地记录暂时读不出来，请稍后再试」，不再把失败显示成「暂无播放记录」。真正没有记录时才显示空态。

「我的」未登录副标题从「登录后同步收藏与观看记录」改成「收藏和观看记录只保存在这台手机」。已登录只显示昵称，不再写「已登录」三字当状态。

### 3.2 发现页海报

```text
+--------------------------------------+
|                                      |
|     （海报放大铺满，多出的裁掉）     |
|                                      |
|  试看 · 详情页可看全片               |
+--------------------------------------+
| 庆余年                               |
| 2019 · 古装  轻触观看完整影片 ›        |
+--------------------------------------+
```

横图不再上下留白或留黑。中心卡开播后视频仍用现有缩放模式，本项不改视频画面。

### 3.3 亮屏不续播

用户在发现页看到画面 → 切到主页 → 画面已停 → 息屏 → 亮屏。亮屏后仍停在主页，发现页那一集不出声。再点「发现」才从断点续播。

用户一直停在发现页、且本身正在播放，息屏再亮可以续播。详情页内嵌播放器和全屏播放器如果在息屏前正在播放，也按同一规则恢复；如果用户已经手动暂停，则不恢复。

### 4.3 亮屏不续播

不把 `heldByUser` 放进 `DiscoverResume`，也不在发现页新增生命周期监听。修 `MainActivity` 现有 `DefaultLifecycleObserver` 的 `onStop/onStart` 即可，因为发现页、详情页、全屏页共用同一个全局引擎。不要另外再注册一个 observer 或覆盖 Activity 的同名方法，否则会出现两次 pause/play。

```kotlin
private var resumeAfterStop = false

lifecycle.addObserver(object : DefaultLifecycleObserver {
    override fun onStop(owner: LifecycleOwner) {
        val engine = PlaybackEngineHolder.peek()
        resumeAfterStop = engine?.isPlaying == true &&
            PlaybackEngineHolder.surfaceCount() > 0
        engine?.pause()
    }

    override fun onStart(owner: LifecycleOwner) {
        if (!resumeAfterStop) return
        resumeAfterStop = false
        if (PlaybackEngineHolder.surfaceCount() > 0) {
            PlaybackEngineHolder.peek()?.play()
        }
    }
})
```

规则：

- `onStop` 先记录“停之前是否真的在播 + 是否还有可见 surface”，再 pause。
- `onStart` 只恢复“生命周期导致的暂停”；用户手动暂停时 `isPlaying == false`，不会恢复。
- 发现页切到主页后 `setSurface(false)` 已经把 `surfaceCount` 降到 0，`onStart` 不会播；仍停在发现页或详情/全屏时 `surfaceCount > 0`，可以恢复。
- 不依赖 `active` 表达用户意图；`active` 仍只用于 pager 前台/surface 计数。
- 把判定抽成纯函数 `shouldResumeAfterStop(wasPlaying, surfaceCount)`（`app` 层）并加 JVM 单测；`MainActivity` 只负责取值和调用。

回归场景：发现页 → 主页 → 息屏/亮屏；发现页停留 → 息屏/亮屏；用户手动暂停 → 息屏/亮屏；详情内嵌 → 息屏/亮屏；全屏 → 息屏/亮屏；Discover → Detail → Back。后三个不能因为修第 3 项而变成不恢复。

- Activity 重建时 `savedInstanceState != null`，即使 NavHost 重新组合也不会自动检查；进程重建时 `startupCheckConsumed` 归零，但只有 `savedInstanceState == null` 的新冷启动才放行。
- `MineScreen` 的手动按钮继续调 `manualCheck(deps)`，不设闸门。

#### 4.9.3 行为

- 冷启动 + 24h 到期 + 有新版本 + 未忽略 → 自动弹一次。
- 冷启动 + 24h 未到 → 不请求，不弹。
- 冷启动 + 检查失败 → 不弹，写 `markChecked`，避免每次冷启动重试。
- 热启动/回前台/旋转/Activity 重建 → 不自动请求，不自动弹。
- 手动检查 → 不受 24h 和冷启动闸门限制；发现新版本仍弹。

## 6. 风险与未决

1. **D1 令牌是阻塞项**：不解决令牌来源，删除令牌设置会让登录/注册直接不可用。推荐先做 debug 维护入口 + release 暂不可用文案。
2. **D2 无限流会重复**：池子有限，轮次复用只能保证“不触底”，不能保证“永不重复”。要永不重复必须新增内容源。
3. **波纹全局关闭会连焦点/悬停一起关**：本项接受；若后续需要键盘/TV 焦点反馈，另加非灰色 outline。
4. **76dp 固定宽度在超大字体下可能裁切**：默认和 1.3x 验收；2.0x 若裁切，改用测量后统一宽度，不退回两个不同宽度。
5. **发现页优选不等于所有片都有全片**：只保证排除已知不可播源、线路优先和全片兜底；兜底失败仍可能试看，必须保留角标。
6. **UI 视觉证据仍是真机人工**：当前没有 Compose UI 测试依赖；不要把 `:ui:jvmTest` 通过当成波纹/按钮/真机行为已通过。
