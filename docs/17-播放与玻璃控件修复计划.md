## 1. 范围

本计划补九处行为：

1. 发现页中心卡全量重试成功后，应自动起播。
2. 换集时，渲染面应按集序号重建。集名相同或为空时，也要清掉上一帧。
3. 从发现页进入详情后，发现页的播放进度应保留。进度小于 3 秒时，历史记录不应盖掉它。正在播放的交接不暂停预览引擎，见第 11 节。
4. 搜索条和底部 Dock 的玻璃底边，应透射正下方那一行内容。Dock 折叠一次后再展开，底边仍应对准正下方，不能错位。
5. 全屏「倍速」和「保留比例」面板打开后，点击面板以外的区域应关闭面板。
6. 进入详情页和发现页播放，都应选中最完整且首集能解析的源，并把首集地址准备好。发现页不得把这种片标成「这部暂时看不了」。
7. 发现页正在播放时点进详情，应保持该播放状态进入。不暂停，不进入缓冲，不重新 `setMedia`。
8. 发现页正在播放时，息屏或退出应用但不杀进程，应立刻暂停。回到前台后，仅当退后台前确实在播且画面仍在时才恢复。
9. 发现页下滑离开当前卡时，上一支应立刻停止。滑到的新卡应尽快出第一帧，不能一直停在加载。

返回发现页后列表不重洗。持有者已经是 `IndexViewModel.discoverUi`（`IndexViewModel.kt:56`，类型 `DiscoverUiState`，`IndexScreen.kt:971`）。本计划只为 `feedFor` 补测试，不搬文件。

以下改动已在当前源码里。本计划不重复做：

- `discoverRawUrl` 先按 `detailCacheKey` 查 `detailCache`。未命中时调用 `fetchDetail(src, vod_id, vod_uri)`，成功后写回缓存。
- 中心卡失败后用 `altLimit = Int.MAX_VALUE` 再解析一次。
- 中心卡就绪后不画海报，底下是黑底。
- 发现页订阅 `PlayerListener.onBuffering`，转圈带暗底。
- 全屏控制栏用固定 6 dp，预览引擎起播缓冲是 2500 毫秒。
- 下载存储的 `appendBytes` / `streamGet` 回退，以及 Gitee 发布工作流。

版本常量当前是 `1.3.27` / `1000327`（实施时由 1.3.26 递增，按 PATCH 发布）。

## 2. 全量重试成功后起播

### 2.1 现状

起播 effect 在 `IndexScreen.kt:1188`：

```kotlin
LaunchedEffect(playingIdx, active) {
```

它等到 `resolved[idx]` 的第一个非 null 结果。这个结果的地址可以是空串。地址是空串时，在 `IndexScreen.kt:1197` 返回，不等待后续写回。全量重试之后才可能写入直链。effect 的 key 不含该地址，所以写回后这段不再执行。卡片可以不再显示「看不了」，但画面不起播。此结果未在真机复测。

`waitForFullSource` 在 `resolveChainOf` 里是常量 `true`。批量预解析和全量重试都等完整源。保持这个常量。

### 2.2 做法

1. 把 `resolved[playingIdx]?.first` 加进 `IndexScreen.kt:1188` 的 `LaunchedEffect` key。
2. 地址仍是空串时，保持 `return@LaunchedEffect`。空地址不应交给引擎。
3. 重试把非空地址写回 `resolved[idx]` 后，key 变化，effect 应再跑，并调用 `setMedia` 与 `play()`。

警告：key 变化会取消正在等待的那次 effect，并在新的一次开头调用 `engine.pause()`。这只应发生在「还没有可播地址」或「地址刚从空串变成直链」时。已在播的同一条直链不应因为重组而重头 `setMedia`。

### 2.3 验证

1. 跑 `rtk gradlew :ui:testDebugUnitTest`。现有 `DiscoverPlaybackRulesTest` 应保持通过。
2. 在 MuMu 上打开一张第一次解析失败、重试能出地址的卡。重试成功后，中心卡应出画。探针里应有该卡的起播记录。真机证据未取之前，文档写「未验证」。

## 3. 换集时清掉上一帧

### 3.1 现状

内嵌播放器已经用片名和集名重建渲染面（`InlinePlayer.kt:466`）：

```kotlin
key(title, episodeName) {
    VideoSurface(...)
}
```

`playInline` 把 `episodeName = ep.name` 交给 `PlaybackSession.play`（`DetailViewModel.kt:948`）。会话状态再写回 `inlineState.episodeName`。两处 `InlinePlayer` 调用都传入了 `episodeName`（`DetailScreen.kt:376`、`DetailScreen.kt:1090`）。

集名相同，或集名为空时，这个 key 不变。同一 `PlayerEngine` 上换集，`TextureView` 会留着上一集的最后一帧。

路由全屏页 `PlayerScreen.kt:369` 的 `VideoSurface` 没有 `key`。上方注释写了 `key(engine)`，调用本身没有包进去。换集时引擎实例若不变，旧帧会留下。

### 3.2 做法

1. 在 `InlinePlayer.kt:466`，把集序号加进 key。建议形式是 `key(title, episodeName, episodeIndex)`。`episodeIndex` 从现有 `inlineEpisodeIndex` 传入。两处 `InlinePlayer` 调用都要传。
2. key 只含片名、集名、集序号。不要把播放地址放进 key，也不要写进日志。
3. 在 `PlayerScreen.kt:369`，用 `key(state.episodeIndex)` 包住 `VideoSurface`。引擎实例变化时仍按现有绑定顺序创建视图。

警告：重建视图会多一次 `TextureView` 创建。换集时可以接受。不要在进度每一秒变化时改变 key。

### 3.3 验证

1. 详情页内嵌位连续切两集，且两集名称相同或都为空。新集出画前应是黑底，不应看到上一集末帧。
2. 从详情进入路由全屏页后再切集，同样不应留下上一集末帧。
3. 真机或 MuMu 截图未取之前，验证记录写「未验证」。

## 4. 发现页进度进详情

### 4.1 现状

点击卡片时，`IndexScreen.kt:1409` 用 `DiscoverPlaybackRules.handoffStartAtMs` 计算 `startAtMs`，并放进 `Routes.detail`。路由和 `NavGraph` 已有 `startAtMs` 参数。点击回调里没有 `engine.pause()`。

`DetailViewModel.playInline`（`DetailViewModel.kt:893`）在 `handoffStartAtMs >= 0` 且 `handoffUsed == false` 时取出交接进度，然后把 `handoffUsed` 设为 true（`:916-918`）。`PlaybackSession.play` 收到 `startAtMs = handoffMs`（`:952`）。

`tryAutoPlay` 在调用 `playInline` 之前，若有交接进度，把 `inlinePositionRestored` 设为 true（`DetailViewModel.kt:1796`）。`playInline` 在 `:930` 又把它设为 false。

`restoreInlinePosition`（`:1310`）看到该标志为 false 时会继续。`InlineSessionGate.canRestoreInline` 在引擎位置小于 `ResumeRestore.HEAD_GUARD_MS`（3000 毫秒，`ResumeRestore.kt:33`）时允许恢复。历史位置因此可以盖掉发现页带来的进度。此路径未在真机复测。

### 4.2 做法

1. 卡片已经在播时，点击不得调用 engine.pause()。同一条流由详情页接管，只有一个声音。未在播的卡片（startAtMs 小于 0）不交接地址，离开发现页后可以暂停预览引擎。
2. 交接进度只用于第 0 集。在 `playInline` 里，仅当 `realIdx == 0` 且 `handoffUsed == false` 时，把 `handoffStartAtMs` 传给 `PlaybackSession.play`。其他集的 `startAtMs` 用 `-1`。
3. 保留 `:930` 的 `inlinePositionRestored = false`，供普通换集重置。若本集 `handoffMs >= 0`，紧接着再设为 true。`restoreInlinePosition` 应在标志为 true 时直接返回。
4. 不要新增第二套交接字段。沿用现有的 `handoffStartAtMs` 和 `handoffUsed`。

警告：先设 true 再在 `playInline` 里设 false，等于没设。标志必须在 `:930` 那次赋值之后仍为 true。

### 4.3 验证

1. 发现页把一条片子播过 3 秒，再点进详情。详情应从发现页的位置继续，不应从 0 或另一条历史位置起播。正在播放的交接应出现 session-skip-setMedia，不应出现 session-setMedia。
2. 点进详情后只有这一条流在出声。发现页预览引擎就是详情正在用的引擎，不要再另起一个引擎。
3. 从搜索或首页进详情时，不带 `startAtMs`。自动播放仍按原有 `ResumeDecide` 走。
4. 真机证据未取之前，`docs/05-真机验证记录.md` 写「未验证」。

## 8. 搜索条与底部 Dock 的底边透射

### 8.1 要求

玻璃底边看到的内容，应是该底边在页面上正下方的那一行。底边的采样 Y 应等于底边自己的 Y。不能整块上移或下移。

2026-11-22 的反馈是：

- 顶部搜索条一直不是这样。它的底边没有直直透射自己的下边。
- 底部 Dock 在第一次折叠之前可以对准。折叠一次并再展开之后，透射错位，底下的内容对不上 Dock 的下边。

### 8.2 现状

采样在 `GlassSurface.kt:142-146`。玻璃用自己的 `positionInRoot()` 减去内容层原点，再把采样图层反向平移：

```kotlin
val dy = self.positionInRoot().y - origin.positionInRoot().y
sampleLayer.record {
    translate(-dx, -dy) { drawLayer(src) }
}
```

`positionInRoot()` 是布局位置。它不含 `graphicsLayer` 上的绘制位移。

搜索条和 Dock 的显隐在 `IndexScreen.kt:410-414` 与 `IndexScreen.kt:491-494`。两边都用 `AnimatedVisibility` 的垂直滑入滑出：搜索条是 `slideInVertically { -it / 2 }`，Dock 是 `slideInVertically { it / 2 }`。第一次进入时可见状态没有跑进入动画。折叠一次后再展开，进入动画会跑。绘制位置因此和 `positionInRoot()` 分开。Dock 的整块采样就错位。

搜索条还有一层始终存在的底边折射。`GlassFx.android.kt:29-30` 把边缘采样沿法线外推：

```text
float fall = smoothstep(0.66, 1.0, r) * uRefract;
float2 uv = clamp(xy + dir * fall, float2(0.0), uSize - float2(1.0));
```

底边的 `dir.y` 为正，`uv.y` 被推到采样图的最后一行。44 dp 高的搜索条短边折射约 2.2 dp（`GlassSurface.kt:109`，短边 5%，钳在 1.5–3 dp）。底边因此看不到正下方那一行。Dock 高 56 dp，这条折射较轻，所以折叠前看起来仍对准。

内容层和玻璃浮层是兄弟节点（`GlassPageBackdrop.kt:183-205`）。内容滚到玻璃后面时，采样应跟着内容走。本项不改这层拆分。

### 8.3 做法

1. 在 `GlassFx.android.kt` 的着色器里，底边不做垂直位移。`uv.y` 在控件下半边的外圈应等于 `xy.y`。左右边缘的折射可以保留。
2. API 33 以下只有模糊、没有这道折射。底边直采样在这些版本上已经成立，不要为它们再加位移。
3. 去掉搜索条和 Dock 的垂直滑入滑出。`IndexScreen.kt:412-413` 与 `:493-494` 只保留 `fadeIn()` / `fadeOut()`。展开后的绘制位置应与 `positionInRoot()` 相同。
4. 不要把播放地址写进玻璃采样或日志。

警告：若仍要滑动动画，必须把同一段 `translationY` 加进 `GlassSurface` 的 `dy`。只改动画、不改 `dy`，折叠一次后还会错位。

### 8.4 验证

1. 首页不滚动时，看搜索条底边。底边里的色块应接上搜索条正下方那一行海报或文字，不能整条上移。
2. 底部 Dock 先下滑收起，再上滑展开。展开后底边应重新对准正下方内容，不能留下半条高度的错位。
3. 内容在搜索条和 Dock 后面滚动时，玻璃里的内容应跟着动。
4. 真机截图未取之前，验证记录写「未验证」。

## 9. 倍速和保留比例点外面关闭

### 9.1 现状

全屏形态的两个面板都在 `InlinePlayer.kt`。

- 「倍速」打开 `SpeedSheetPanel`（`:814`）。档位点击后调用 `onDismiss`。
- 「保留比例」是 `zoomLabel` 的 FIT 文案（`FullscreenUiPolicy.kt:26`）。它打开 `ZoomSheetPanel`（`:802`）。选项点击后调用 `onDismiss`。

画面单击在 `InlinePlayer.kt:429`：

```kotlin
onTap = { controlsVisible = !controlsVisible }
```

这次点击不改 `speedSheet` 和 `zoomSheet`。面板的可见条件是 `zoomSheet && controlsVisible` 与 `speedSheet && controlsVisible`（`:803`、`:815`）。点画面只会藏起控制栏，两个布尔值仍为 true。控制栏再次出现时，面板还在。

点控制栏上的其他按钮，同样不会把这两个布尔值设为 false。`onDismiss` 只挂在面板内部的选项上。

下拉打开时，`shouldAutoHideControls` 因 `dropdownOpen` 为 true 而不自动隐藏（`FullscreenUiPolicy.kt:47`）。面板会一直留着，直到点到某个选项。

### 9.2 做法

1. 在 `FullscreenUiPolicy.kt` 增加纯函数：面板打开时，外部点击应关闭两个面板，并且这一次点击不切换控制栏。返回值包含「倍速是否打开」「保留比例是否打开」「是否切换控制栏」。
2. 在 `InlinePlayer.kt:429` 的 `onTap` 里调用该函数。任一面板打开时，把 `speedSheet` 和 `zoomSheet` 都设为 false，不要同时执行 `controlsVisible = !controlsVisible`。
3. 两个面板都关闭时，单击仍只切换控制栏。双击播放暂停保持现状。
4. 在面板下面加一层全屏点击层，仅在任一面板打开时存在。点击该层执行同一次关闭。这样点到控制栏空白、进度条以外的区域也会关闭。点击层必须放在两个面板之下，面板上的档位点击仍要能选中并关闭。
5. 在 `FullscreenUiPolicyTest` 补三条：只开倍速时外部点击后两者都关闭；只开保留比例时同样关闭；两者都关闭时外部点击改为切换控制栏。

警告：关闭面板的那一次点击不要把控制栏一起藏起来。否则用户点外面后面板没了，按钮也没了。

### 9.3 验证

1. 全屏打开「倍速」，点画面、点控制栏空白、点「保留比例」以外的区域。面板应关闭，控制栏应仍在。
2. 全屏打开「保留比例」，做同样的外部点击。面板应关闭。
3. 两个面板都关闭时，单击画面仍只切换控制栏。
4. 跑 `rtk gradlew :ui:testDebugUnitTest`。`FullscreenUiPolicyTest` 的新断言应通过。
5. 真机未点过之前，验证记录写「未验证」。

## 10. 详情和发现页都候着最好的源

### 10.1 要求

点进详情后，应选中最完整且首集能解析的播放源，并把该源首集地址准备好。用户不用再手动刷新播放源。

发现页自动播放用同一套选源。同一部片在发现页不得显示「这部暂时看不了」，而进详情刷新播放源后又可以播。

「最好」沿用现有规则，不另起一套：

1. 候选必须已经知道集数，且集数大于 0。
2. 当前源有 `playGap` 时，任何有集数的候选都更好。
3. 否则只在候选集数严格多于当前源时才换。
4. 集数相同则保持 `findAltSources` 的原有顺序。
5. 换过去之前，首集地址必须能解析出来。集数多但解析失败的源跳过。

### 10.2 现状

这套规则已经在 `BestSourcePolicy.kt` 的 `rankedSwitchTargets`。详情页 `maybeAutoPickBestSource`（`DetailViewModel.kt:565`）按它试前 3 名（`ALT_AUTO_PICK_TRIES = 3`），首集可解析才 `switchToSource`。

详情进页时并不等这个结果。`loadDetail` 先用卡片自带的源画详情、`tryAutoPlay`，并在 `applyDetail` 里 `startPreResolve`（`:403-406`）。`loadAltSources` 排在主详情请求之后（`:354`）。自动换源要等每个候选的详情预取带回集数（`prefetchOne` → `maybeAutoPickBestSource`）。所以进页后候着的是卡片源，不是最完整的源。

发现页不走 `rankedSwitchTargets`。`resolveChainOf` 默认 `altLimit = 3`（`IndexScreen.kt:1108`）。`findFullSource` 只取候选列表的前 3 个，再按列表顺序等第一个能解析的地址（`PlaybackSession.kt:587-604`）。这 3 个是搜索先返回的源，不是集数最多的源。

`findAltSources` 在 `PageBudget.ALT_SOURCES_BUDGET_MS` 到点后先返回已到达的快照（`SourceRepository.kt:1056-1062`）。全部源跑完才把完整列表写入缓存（`:1087-1090`）。发现页若在快照阶段解析失败，会把空地址写进 `resolved`（`IndexScreen.kt:1163`）。中心卡之后最多再试 3 次（`DiscoverPlaybackRules.MAX_CENTER_RETRY`）。3 次用尽后 `showFailure` 为 true，卡片显示「这部暂时看不了 · 下拉换一批」（`IndexScreen.kt:1352`、`:1520`）。

此时详情页再刷新播放源，缓存里往往已经是完整列表。`maybeAutoPickBestSource` 能选到发现页前 3 个快照里没有的源，所以同一部片又能播。

起播 effect 仍是 `LaunchedEffect(playingIdx, active)`（`IndexScreen.kt:1188`）。空地址在 `:1197` 返回。后面的重试即使写回直链，这段也不再执行。这和第 2 节是同一处。

### 10.3 做法

1. 详情进页后，主详情和选源并行。选源使用 `findAltSources` 的完整列表，不用 6 秒快照做最终判定。完整列表按 `rankedSwitchTargets` 排序，再按现有 `firstEpPlayable` 试前 3 名。
2. 选中的源优于卡片源，且用户还没有手动选源时，调用现有 switchToSource(automatic = true)，并让 startPreResolve 候着该源首集。卡片源集数不少于候选、且没有 playGap 时，保持卡片源。发现页正在播放并已交接时，不要在进入详情的这一刻换源或 setMedia。更好的源只候着，等这一集播完或用户自己换源再用。交接规则见第 11 节。
3. 发现页中心卡用同一套排序和首集校验。`altLimit = 3` 只允许用来提前起播，不允许用来写下最终失败。
4. 6 秒快照里若已经有可播全片，发现页可以先播。快照里没有，先保持加载，不得写入空地址。完整列表回来后，若有集数更多且首集可解析的源，换上该地址，播放进度保留。
5. 只有完整列表里也没有可解析首集时，才允许 `showFailure`。重试或完整列表写回非空地址后，按第 2 节把该地址放进起播 effect 的 key，使中心卡自动起播。
6. 单测保持 `BestSourcePolicyTest` 的现有排序。再补两条：快照为空不得当成最终失败；完整列表里集数更多且标记为首集可解析的源应被选中。

警告：不要为了选源放宽 URL 校验，也不要在发现页对每一张可见卡都拉全部源的详情。全量选源只给当前中心卡和刚打开的详情页。前 3 张的预解析仍用现有 `altLimit = 3`，只负责提前起播。

### 10.4 验证

1. 找一部现在发现页会显示「这部暂时看不了」、进详情刷新播放源后能播的片子。发现页应在完整候选返回后自动起播，不再要求下拉换一批。
2. 点进该片详情，不手动刷新。播放源应落在集数最多且首集能解析的那一条，首集地址应已在预解析结果里。
3. 卡片源本身就是全集且首集可解析时，详情不应跳到另一个源。
4. 跑 `rtk gradlew :ui:testDebugUnitTest` 和 `rtk gradlew :shared:jvmTest`。
5. 真机未复测之前，`docs/05-真机验证记录.md` 写「未验证」。


## 11. 发现页播放中进入详情保持原状态

### 11.1 要求

发现页的视频正在播放时，点击卡片进入详情，播放状态应与点击前相同。

- 不暂停。
- 不进入缓冲。
- 不重新加载媒体，不调用 setMedia。
- 播放进度、正在使用的地址、播放中或暂停中的状态都保持不变。
- 画面可以从卡片矩形移到详情播放位。移动期间仍是同一个引擎、同一段流。

未在播放的卡片（还在解析、已经失败、只有海报）不走这条路径。详情页按自己的起播逻辑处理。

### 11.2 现状

点击正在播放的卡片时，IndexScreen.kt:1430 记下 startAtMs，DiscoverHero.record 记下卡片矩形，DiscoverHandoff.record 记下当前地址和进度（:1449-1461）。

详情页 adoptDiscoverHandoff（DetailViewModel.kt:416）把这条地址放进 preResolved，从而跳过再解析。PlaybackSession.play（PlaybackSession.kt:236-272）在会话还没有引擎、且预览引擎的 currentUrl 与这条地址相同时，接管预览引擎，并在 sameMedia 时跳过 setMedia。

这条路径仍会打断播放，原因有三处：

1. 离开发现页时，IndexScreen.kt:1302 的 DisposableEffect 调用 setSurface(false)。PlaybackEngineHolder.surfaceInactive 在表面计数归零时暂停主引擎和预览引擎（PlaybackEngineHolder.kt:162-166）。详情页要到 attachInlineSurface（DetailViewModel.kt:793）才把计数加回来。中间计数为 0，预览引擎已经被暂停。
2. 发现页起播 effect 在 IndexScreen.kt:1194 一进入就 engine.pause()。窗格 active 变 false 时也会走到这里。
3. 接管之后，PlaybackSession.kt:272 在 startAtMs 大于 0 时仍 seekTo。play() 在 :282 总会再调用一次。seekTo 会把已经在播的流打回缓冲。playInline 里若把 inlinePositionRestored 清掉，历史恢复还会再 seek 一次。

另外，adoptDiscoverHandoff 在已有会话时直接放弃（DetailViewModel.kt:427）。放弃之后详情会重新解析并 setMedia。

### 11.3 做法

1. 点击时若 startAtMs 大于等于 0 且 engine.currentUrl 非空，先给宿主打一个交接中标记，再 onOpenDetail。这个标记存在时，surfaceInactive 不得暂停预览引擎。
2. 发现页 DisposableEffect 离开时仍可 setSurface(false)，但在标记为交接中时不要把预览引擎暂停。详情 attachInlineSurface 登记表面后，清掉该标记。
3. IndexScreen.kt:1194 的 engine.pause() 在交接中不得执行。未交接的离开（滑走、回首页、失败卡）仍要暂停，避免后台继续出声。
4. PlaybackSession.play 接管预览引擎且 currentUrl 相同、引擎已经在播时：不 setMedia，不 seekTo，不把状态改成 Buffering，不再调用 play()。引擎已经暂停时，只恢复暂停前的状态，仍然不 setMedia。
5. playInline 在这次交接里保持 inlinePositionRestored 为 true。restoreInlinePosition 直接返回，避免历史进度再 seek。
6. 第 10 节的自动换源在这次交接期间不调用 switchToSource。更好的源只写入候选项，不替换正在播的地址。
7. 几何动画继续用现有 DiscoverHero。动画只改 graphicsLayer 的平移和缩放，不碰引擎。

警告：表面计数归零时的暂停是为了返回首页后不再出声。交接标记必须在详情销毁或交接失败时清掉。清掉之后，最后一个表面离开仍要暂停。

### 11.4 验证

1. 发现页中心卡已经出画并在播放。点进详情。进页过程中声音不中断，画面不黑，不出现「正在缓冲…」或「正在解析播放地址…」。探针应有 session-adopt-preview 和 session-skip-setMedia，不应有 session-setMedia，也不应有 no surface left, paused。
2. 进详情后进度与点击前连续，不跳回 0，也不跳到另一条历史记录。
3. 发现页未在播的卡片点进详情，仍按详情自己的逻辑起播。返回首页后声音应停。
4. 真机未复测之前，docs/05-真机验证记录.md 写「未验证」。
## 12. 息屏和退后台必须停掉发现页

### 12.1 要求

发现页正在播放时：

- 按下主页或切换到别的应用，但不划掉本进程：声音应立刻停止，画面不再继续播。
- 息屏：声音应立刻停止，画面不再继续播。

回到前台或亮屏后，只有退后台前确实在播、且播放表面仍在时才恢复。用户若已暂停，亮屏不得自己开播。这条与计划 14 的 NFR-007 相同。

### 12.2 现状

MainActivity 在 onStop 里暂停引擎，在 onStart 里按 shouldResumeAfterStop 决定是否恢复（MainActivity.kt:72-99）。注释写明：发现页这类组合还活着的播放位，退后台不会销毁组合，必须在 onStop 停声。

实际调用的是 PlaybackEngineHolder.peek()（:77、:98）。peek() 只返回主引擎 instance（PlaybackEngineHolder.kt:176）。发现页用的是 previewEngine()（IndexScreen.kt:1049 一带），实例在 previewInstance。息屏和退后台都走 Activity.onStop，但 onStop 不停 previewInstance，所以预览引擎继续出声、继续播。

这是回归。主引擎的 onStop 暂停已经在。发现页改成独立预览引擎之后，这条暂停没有覆盖到预览引擎。

onStart 也只对 peek() 调用 play()。即使补上预览引擎的暂停，回来时若仍只恢复主引擎，发现页会一直停着。恢复必须作用在退后台时正在播的那一台引擎。

### 12.3 做法

1. 在 PlaybackEngineHolder 增加一个只读查询：当前正在播的引擎。主引擎和预览引擎谁的 isPlaying 为 true，就返回谁。两个都在播时，两个都要能被暂停。
2. MainActivity.onStop 对 peek() 和 previewEngineIfAny() 都调用 pause()。wasPlaying 改为：两者之中有一个在播，且 surfaceCount 大于 0。
3. MainActivity.onStart 仍用 shouldResumeAfterStop。条件成立时，对退后台前正在播的那一台调用 play()。只暂停、不记录是哪一台，会导致发现页回前台无法恢复。
4. 给 ForegroundResumePolicy 补测试：退后台前预览引擎在播且表面还在，应恢复；预览引擎已暂停，不应恢复。暂停动作本身放在 Activity，测试只锁判定。
5. 不在发现页的组合销毁里再加一套息屏暂停。息屏不销毁组合，只有 Activity.onStop 收得到。

警告：第 11 节的交接标记只禁止「表面计数归零」时暂停预览引擎。它不得阻止 onStop 暂停。息屏和退后台必须停声，即使交接标记还在。

### 12.4 验证

1. 发现页中心卡正在出声。按主页，不划掉进程。声音应在离开的瞬间停止。探针 foreground-stop 的 wasPlaying 应为 true。
2. 再回到应用。若离开前正在播且发现页仍在，应恢复播放。探针应有 foreground-resume。
3. 发现页正在出声时息屏。声音应停止。亮屏后按第 2 步同一规则恢复。
4. 详情页或全屏正在播时重复第 1 步。主引擎也应停止，回前台规则不变。
5. 真机未复测之前，docs/05-真机验证记录.md 写「未验证」。


## 14. 发现页换卡立刻停，新卡先出画面

### 14.1 要求

发现页当前卡正在播放时，手指向下滑动去看下一条，上一支应立刻停止。声音和画面都停。

手指停下后，视口中心那一条应尽快出第一帧。不能停在加载转圈上。

### 14.2 现状

换片只在滚动停止后才发生。IndexScreen.kt:1275 只观察 isScrollInProgress。滚动中直接 return（:1278），playingIdx 不变。起播 effect（:1188）因此不会 pause。上一支一直播到手指停下。

停下后，中心卡要等 resolveChainOf。该函数默认 altLimit = 3，并且 waitForFullSource = true（:1108、:1121）。试看链会在这里最多等 12 秒才返回（PlaybackSession.kt:676-681）。出网许可只有 Semaphore(2)（IndexScreen.kt:1081）。可见卡和前 3 张预解析都占这 2 个许可，还都在等全片。中心卡排到队时，用户看到的就是一直加载。

预览引擎起播缓冲已经是 2500 毫秒。卡顿不在这 2.5 秒，而在出地址之前的等待。

### 14.3 做法

1. 滚动过程中也计算当前 playingIdx 那张卡的可见比例。比例低于 0.55 时，立刻把 playingIdx 设为 -1。现有起播 effect 会 pause，上一支停止。
2. 滚动停止后，仍取视口中心、可见比例不低于 0.55 的卡作为新的 playingIdx。不要在手指还在滑的时候就起播下一条。
3. 中心卡的解析把 waitForFullSource 设为 false。先返回第一条能播的地址（直链或试看链），起播 effect 马上 setMedia 并 play。全片搜索放到后台，找到后再换，进度保留。
4. 非中心卡不要用 waitForFullSource = true 占满 Semaphore(2)。前 3 张和可见卡只做轻量预取：命中 detailCache 或拿到第一条可播地址即可。中心卡优先占用许可。
5. 预览缓冲保持 2500 毫秒。不要改回 15000。

警告：滚动中只暂停，不起播下一张。否则滑过的每一张都会响一下。

### 14.4 验证

1. 发现页中心卡正在出声。手指下滑。声音应在当前卡离开中心时停止，不等手指抬起。
2. 手指停在下一张。该卡应出画面。不应一直停在转圈，直到跨源全片搜索结束。
3. 只有试看地址时可以先播试看。全片到达后换上，进度不回到 0。
4. 真机未复测之前，docs/05-真机验证记录.md 写「未验证」。
