## 1. 结论

`Android + iOS + HarmonyOS` 三端 target 已经能在**同一个 Gradle 构建**里并存：
`androidTarget`、`iosArm64` / `iosSimulatorArm64`、`ohosArm64` / `ohosX64`。

代价是整仓只能走 CPF（毕昇）一条 Kotlin 线：`KGP 2.2.21-1.2.0` + `CMP 1.9.2-1.2.0`
+ `AGP 8.13.2` + `Gradle 8.14.3`。原 `DengYing` / `DengYingIos` 用的官方
`Kotlin 2.4.21` + `CMP 1.11.1` 在本工程不再可用——官方 KGP 没有 `ohosArm64` / `ohosX64`。

## 2. 为什么两条线不能共存

- 官方 KGP 不提供 `ohos*` target，鸿蒙只能靠 CPF 定制发行版。
- 反过来，CPF 发行版能同时提供 Apple 与 OHOS target，但**只在 macOS host 上是全并集**：
  `kotlin-native-prebuilt-2.2.21-1.2.0-macos-aarch64` 里有 24 个 platform 目录
  （ios_arm64 / ios_x64 / ios_simulator_arm64 / macos / ohos_arm64 / ohos_x64 都在）；
  Windows host 的发行包 `klib/platform` 只有 android / linux / mingw / ohos，**没有任何 Apple 平台库**。
- 因此在 Windows 上编 iOS，必须先用 `runscript/prepareApplePlatformLibs.ps1`
  从官方发行包（`kotlin-native-prebuilt-windows-x86_64-2.2.*`）复制
  `ios_arm64`、`ios_x64`、`ios_simulator_arm64` 三个目录进 CPF 发行包。
  不补的表现是：`compileKotlinIosArm64` 报
  `Cannot access class 'UIViewController'` / `Unresolved reference 'platform'` / `'UIDevice'`。

## 4. 版本与依赖决策

- `gradle/libs.versions.toml`：`kotlin = "2.2.21-1.2.0"`、`composeMultiplatform = "1.9.2-1.2.0"`、
  `lifecycleKmp = "2.9.4-1.2.0"`、`navigationKmp = "2.9.4-1.2.0"`、`savedstateKmp = "1.3.3-1.2.0"`。
  1.2.0 线在 eazytec Nexus 上的 plain 坐标已逐个核实返回 200。
- `playServicesCastFramework = "22.3.1"`（不是 23.0.0）：23.0.0 的 AAR 里
  `META-INF/*.kotlin_module` 是 Kotlin 2.4.0 metadata，CPF 的 2.2.21 直接报
  `Module was compiled with an incompatible version of Kotlin. The binary version of its metadata is 2.4.0, expected version is 2.2.0`。
  22.3.1 是 Kotlin ≤2.2 编的最后一个稳定版，投屏 API 面与 23.0.0 一致。
- `androidx.mediarouter = "1.8.1"`，`app/build.gradle.kts` 用
  `resolutionStrategy.force(...)` 压住 cast 传递来的低版本，避免重复类。
- `serialization 1.9.1-1.1.0-02`、`coroutines 1.10.2-OH-110` 保持 CPF 线现有最高版本（无 1.2.0 线构件）。
